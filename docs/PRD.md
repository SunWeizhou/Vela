## 1. 产品定位与核心理念

### 1.1 一句话定位
**Vela 是建立在 Apple 健康之上的个人身体面板与 AI 健康分析助手：帮助用户看见当前身体状态和长期趋势，理解变化原因，并将这种理解转化为训练与生活调整建议。**

### 1.2 核心原则
> **核心原则**：不做只陈列指标、不能解释个人状态和变化的健康数据面板。

### 1.3 核心价值层级（不可颠倒）
1. **看见身体数据**：把 Apple Health / Apple Watch 分散的体征与信号完整汇聚、清晰呈现；
2. **理解当前状态与长期变化**：通过多尺度趋势（7天 / 30天 / 6个月 / 3年）与 Personal Health Brief 理解身体稳态与偏离；
3. **由 Agent 解释原因、联系不同信号**：AI 分析师提供跨系统关联观察与候选影响因素假设，探讨体征、压力、睡眠与行为之间的联系；
4. **在需要时给出训练与生活建议**：将对身体的理解落地为克制、明确、符合生理负荷边界的行动方案。

## 2. 目标用户与使用场景

### 2.1 Primary User（核心用户）
- **定义**：拥有约 1100 天真实 Apple 健康数据积累、佩戴 Apple Watch、日常从事高强度脑力/科研工作、保持力量训练习惯且有长期健康减脂目标的产品作者本人。
- **阶段原则**：在个人 Daily Driver 阶段，真实作者的连续使用体验与真实反馈是产品最高优先级的需求输入；不引入假设性大众用户的妥协设计。

### 2.2 真实使用习惯契约
- **手表主导记录**：Apple Watch 负责全天体征监控、心率采集以及运动现场记录；用户在训练过程中不操作手机记组、记动作；
- **手机主导决策与解释**：iPhone 负责同步数据、计算身体状态、呈现多尺度趋势、由 AI 深度推理原因并给出行动建议；
- **长线柔性轮转**：力量训练按肌群轮转推进（如背、胸、肩、腿、手臂/核心），不强制绑定星期几；
- **保护健康节律**：当短期减脂目标、训练打卡与身体恢复产生冲突时，Vela 始终优先保护并恢复可持续的健康节律。

## 3. 北极星指标：Trusted Health Brief Day

**`Trusted Health Brief Day`（可信身体简报日）** 是 Vela 的唯一北极星标准：
> **评判标准**：一天中，Vela 是否可靠地回答了用户的三个根本问题：
> 1. **我现在身体总体怎么样？**（How am I overall right now?）
> 2. **最近发生了什么值得注意的变化？**（What has changed recently?）
> 3. **我是否需要采取行动？**（Do I need to take action?）

- **价值均等原则**：身体状态稳定、无需改变计划的一天，与触发减量或调整的一天具有同等完整的价值；
- **非目标指标**：不以打开次数、停留时长、聊天消息数或单纯刷高健康分数作为北极星。

## 4. 核心产品主线

```text
Apple Health / Watch 身体信号同步
    ↓
Daily Health Computation 生成规范 Scored Health Evidence
    ↓
HealthTrendEngine 计算多尺度趋势（7d / 30d / 6m / 3y）
    ↓
生成 Personal Health Brief（全局权威认知对象）
    ↓
┌───────────────┬───────────────┬───────────────┬───────────────┐
│     Today     │    Trends     │     Vela      │   Training    │
│  呈现当前状态  │  呈现长期变化  │  解释关联因素  │ 下游派生决策  │
└───────────────┴───────────────┴───────────────┴───────────────┘
    ↓
后续真实数据更新与主观反馈校准模型判断
```

## 5. 一级信息架构（四大工作区）

Vela 采用清晰的 4-Tab 导航结构，Settings 收敛为系统级二级界面：

```text
Vela App
├── Tab 1: Today（今日状态与地平线）
├── Tab 2: Trends（多尺度趋势与指标详情）
├── Tab 3: Vela（AI 分析工作台与记忆档案）
└── Tab 4: Training（训练负荷与智能决策）
    └── Settings（设置、数据覆盖、权限与控制，右上角/二级入口）
```

### 5.1 Tab 1 · Today（今日状态与健康地平线）
- **核心定位**：回答“我现在怎么样？今天最重要的决定是什么？”；
- **首屏元素**：
  - **健康地平线（Rhythm Horizon）**：随时间展开的恢复、负荷与能量可承受容量窗口；
  - **今日核心决定**：一个首要行动建议（如保持训练、主动恢复、调整作息）；
  - **支撑证据**：2–3 个直接驱动该决定的关键体征证据（如 HRV 偏离、静息心率基线对比）；
  - **辅助行动**：最多 2 项来自睡眠、饮食或压力的辅助调节；
  - **一句话晨间简报**：直击要点的身体状态摘要。

### 5.2 Tab 2 · Trends（多尺度趋势与指标详情）
- **核心定位**：回答“最近身体发生了什么长期变化？”；
- **首屏元素**：
  - **多尺度时间维度**：支持 7 天、30 天、6 个月、3 年的历史基线对比；
  - **核心指标分组**：恢复（Recovery）、睡眠（Sleep）、负荷（Strain）、压力（Stress）、能量（Energy）；
  - **基线偏离标记**：直观展示指标是处于稳态区间，还是显著偏离个人历史基线；
  - **二级详情页**：提供高精细度历史图表、内日分布与统计分位数。

### 5.3 Tab 3 · Vela（AI 分析工作台与对话）
- **核心定位**：回答“为什么会发生这种变化？如何联系不同体征？”；
- **首屏元素**：
  - **动态晨间生理问候**：结合当前恢复分与身体状态生成的情境问候；
  - **智能情境提问气泡**：基于当日生理偏离动态生成的 4 个高价值分析提问；
  - **对话推理主场**：基于结构化事实快照（Canonical Fact Snapshot）展开的跨系统关联分析；
  - **健康记忆与报告入口**：顶层收敛的“健康记忆档案（Wiki）”与“历史分析报告”胶囊。

### 5.4 Tab 4 · Training（训练负荷与智能决策）
- **核心定位**：回答“今天适合怎么练？肌群恢复就绪度如何？”；
- **首屏元素**：
  - **今日决策与负荷边界 Hero**：决策定调（保持/减量/换部位/恢复）+ 3 大客观边界（`容量乘数 %` · `RPE 强度上限` · `建议时长`）；
  - **三日轮转预测流**：展示今明后 3 天的肌群轮转规划；
  - **手表同步运动复盘**：展示 Apple Watch 自动同步的最新运动记录（心率区间、负荷产生、能量消耗）；
  - **局部肌群超量恢复图谱**：胸、背、腿、肩、臂、核心各肌群近 7 天组数负荷与三态徽章（🟢 可练 · 🟡 留量 · 🔴 避开）；
  - **5 周训练节律热力图**：长线训练日历走势。

### 5.5 Settings（设置、权限与数据控制）
- **组织方式**：作为二级页面由各 Tab 顶部或个人入口拉起，不占用一级 Tab；
- **功能职责**：Apple Health 权限授权、数据覆盖度检查、数据源同步控制、AI Provider / API Key 配置、数据导出与删除。

## 6. 数据与 AI 交互边界

### 6.1 本地规则与 AI 的职责划分
| 领域 | 本地计算引擎（Local Engine） | AI Agent / Cloud LLM |
| :--- | :--- | :--- |
| **健康评分** | 唯一负责（0–100 分数由本地确定性算法计算） | **禁止重算**；仅读取并引用已有分数 |
| **训练安全边界** | 唯一负责（计算容量乘数、RPE 上限、硬性禁忌） | 提出调整建议时不得突破本地安全上限 |
| **原因解释与关联** | 计算统计学相关性与基线偏离 | 负责自然语言推理，联系睡眠、压力、行为提出候选假设 |
| **计划变更** | 存储并维护正式 `DailyOperatingPlanRecord` | 生成待审查的 `Plan Proposal`，**必须经用户确认** |

### 6.2 语言与归因规范
- **禁止断言生理因果**：AI 可以提出“候选影响因素”（Candidate Drivers）和“观察到的关联”（Observed Correlations），但严禁向用户宣称确定的因果结论；
- **缺失数据客观表达**：未采集或同步的数据显示 `--` 或说明数据缺失，严禁伪造健康数据或将未填写自评默认为“无压力/无酸痛”。

## 7. 产品非目标（Non-Goals）

1. **不做泛健康数据罗盘**：不堆砌无解释力的生硬数字与复杂图表；
2. **不做手动记组工具**：不强迫用户在 iPhone 上记录动作、组数、重量与组间休息（交给 Apple Watch 自动采集）；
3. **不做强制热量记账与惩罚性补偿**：不推崇用惩罚性有氧或极端节食去“抵消”暴饮暴食；
4. **不做医疗诊断与虚假健康年龄**：不提供虚假的“生物学年龄预测”作为营销噱头，不提供严肃医疗诊断；
5. **不脱离用户确认静默改写计划**：AI 的任何调整方案均须经用户 Explicit Confirmation 才能生效。

## 8. 当前阶段优先级与演进路径

1. **P0 · 核心体验闭环打磨**：
   - 完善 `PersonalHealthBrief` 规范投影，打通 Today、Trends、Vela、Training 统一事实源；
   - 保证 Apple Watch 同步数据的即时呈现与局部肌群疲劳模型的稳定性。
2. **P1 · 解释与上下文深度增强**：
   - 优化 AI Agent 对长期多尺度趋势（30天/6个月/3年）的统计洞察与候选因素关联质量；
   - 健全 Wiki 记忆档案的自愈与提炼机制。
3. **P2 · 个人响应模型校准**：
   - 支持对 Agent 洞察进行轻量标记（正确/部分正确/不正确），持续校准个人基线模型。
