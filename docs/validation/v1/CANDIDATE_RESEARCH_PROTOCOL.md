# Vela 下一代算法候选研究协议 (Candidate Research Protocol)

版本：1.0.0  
生效日期：2026-09-06  
归属任务：Card V1 (算法可复跑比较与模型卡)  
状态：候选研究协议规范（正式生效，用于指导未来算法迭代）

---

## 1. 研究背景与核心伦理原则 (Background & Ethics)

### 1.1 现实基线与诚实原则
- **事实基线**：当前 Vela v1.0.0 的五大健康评分（恢复、睡眠、负荷、压力、能量）均基于文献启发的启发式规则与确定性稳健统计量（中位数、MAD、Z-Score、Sigmoid 压缩）。
- **红线约束**：**严禁将单元测试通过（Synthetic Correctness）伪称为临床或生理有效性证明**。严禁在没有合法伦理审查和受试者明示同意的数据集上宣称临床 AUC 或真实相关系数。

### 1.2 数据隐私与知情同意协议 (Privacy & Informed Consent Protocol)
任何用于评估或训练下一代算法候选模型的真实用户生理数据，必须严格遵循以下协议：
1. **完全本地化优先**：所有数据重放与模型参数调优默认在用户端设备（On-Device CoreML/Swift）执行。
2. **脱敏与最小化**：若需收集留出测试集，必须剥离姓名、Apple ID、地理位置、具体时间戳偏移（使用相对天数），仅保留脱敏的生理特征值（HRV、RHR、体温偏差等）。
3. **明示授权与撤回**：受试者必须单独勾选《Vela 算法科研改进知情同意书》，并享有随时一键删除其历史科研数据样本的权利。
4. **零第三方泄露**：严禁将原始生理波形、采样序列或用户日志上传至公共仓库或第三方非合规分析平台。

## 2. 候选假设制定规范 (Hypothesis Formulation: One at a Time)

未来任何算法修改必须提出明确的单一因果假设，严禁将多个参数修改混杂在同一版本中。

### 候选假设示例 1（恢复评分）：
- **假设 H-REC-01**：在夜间手腕温度偏离基线 $+0.5^\circ\text{C}$ 至 $+1.5^\circ\text{C}$ 的轻微发热早期区间，使用连续对数-Sigmoid 平滑惩罚替代当前的固定 $-8.0$ 分硬阶梯，能够降低在临界阈值点处的评分突变跳跃（减少相邻日抖动 $> 10$ 分的偶发个例），同时不降低对真实感染发热的主观预警敏锐度。

### 候选假设示例 2（睡眠评分）：
- **假设 H-SLP-01**：将 REM 睡眠比例（$15\%–25\%$ 为适宜区间）作为调节因子引入时长满分后的辅助微调（权重 $\le 10\%$），相比仅依靠“时长+一致性+清醒中断”的当前三维模型，在受试者自评清醒精力（Morning Alertness Scale）上的秩相关系数 $\rho$ 预期提升 $\ge 0.05$。

## 3. 比较基线与对照组设计 (Baseline & Controls)

任何新算法或复杂模型（如树模型、深度神经网络）必须与以下两个“简单基线 (Simple Baselines)”进行严格对比：
1. **天真基线 (Naive Baseline)**：
   - 恢复：直接以个人 7 天滚动 RHR 相对于 28 天中位数的线性偏离作为单一因子。
   - 睡眠：直接以“昨夜睡眠时长 / 目标时长 $\times 100$”作为单一因子。
2. **当前生产规则基线 (Production v1.0.0 Baseline)**：
   - 即以当前 commit 运行的 `DailyHealthComputation` 输出作为对照组。

若候选模型在留出测试集上的增益无法显著超越天真基线（$p < 0.05$ 且效应量具有实际生理意义），则依据奥卡姆剃刀原则予以否决，保留简单启发式。

## 4. 消融与敏感性分析实验设计 (Ablation & Sensitivity Design)

### 4.1 逐项消融协议 (Leave-One-Out Ablation)
针对包含多因子的复合模型（如恢复评分 4 个主分量 + 4 个红旗因子），必须依次进行逐项置零/剔除测试：
- **Ablation 1**：移除体温偏离惩罚，观察极端发热场景的输出变化；
- **Ablation 2**：移除昨日负荷惩罚，观察大强度长跑次日的恢复评分变化；
- **Ablation 3**：移除入睡一致性惩罚，观察周末作息推迟但睡足时长场景的评分变化。

### 4.2 局部敏感性扰动 (Local Sensitivity Perturbation)
- 对关键输入参数（如今日 HRV 输入）施加 $[-20\%, +20\%]$ 的连续阶梯扰动（步长 $2\%$）；
- 记录输出分数的雅可比导数 $\frac{\partial \text{Score}}{\partial \text{Input}}$；
- **合格判据**：导数曲线必须全局连续且有界，不存在局部不连续跳变点（Discontinuity Jump）。

## 5. 评价指标与不确定性报告规范 (Evaluation Metrics & Uncertainty)

在未来获得合法真实标注队列后，评估报告必须包含以下维度，严禁仅报单个平均值：
1. **平均绝对误差 (MAE) 与 中位绝对误差 (MedAE)**：评估预测偏差的集中趋势。
2. **斯皮尔曼等级相关系数 (Spearman $\rho$) 与 95% 置信区间 (Bootstrap 1000 次)**：评估相对排序单调性。
3. **校准曲线 (Calibration Curve) 与 Brier 分数**：评估状态分段（Low/Medium/High）的概率校准度。
4. **不确定性区间报告**：对每一个测试点，必须给出基于个人近期方差估计的预测置信区间（如 $[62 \pm 4]$ 分）。

---

## 6. 生产隔离与发布准入机制 (Shadow Pipeline & Release Gating)

为避免未经临床或同行审阅的试验模型意外污染生产环境，实行严格的双轨运行与发布准入机制：

```
[HealthKit Snapshot] 
         │
         ├───> [Production Pipeline: DailyHealthComputation v1.0.0] ───> [User UI / Widgets / Live Store]
         │
         └───> [Shadow Research Pipeline (Debug Only)]
                     │ (Feature Flag: ENABLE_RESEARCH_CANDIDATE=0)
                     └───> [Candidate Scoring Engine] ───> [docs/validation/research_logs.json]
```

### 准入与发布检查清单：
- [ ] 该候选算法在离线 10 大合成场景重放中 100% 通过且无回归；
- [ ] 敏感性分析表明无极端突变点；
- [ ] 真实留出队列上效果统计显著超越基线；
- [ ] 内存峰值增加 $< 2\text{MB}$，计算延迟 $< 5\text{ms}$；
- [ ] 经过架构委员会（ADR 流程）与产品医学/运动顾问签字同意；
- [ ] 在 `ScoringAlgorithmVersions` 中正式递增版本号（例如更新为 `1.1.0`），旧版本计算逻辑归档至 `docs/archive/`。
